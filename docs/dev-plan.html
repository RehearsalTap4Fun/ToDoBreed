§03

系统架构与数据流

核心原则：引擎层全部纯函数。UI 不直接改状态，所有变更走 engine.ts 的纯函数，返回新状态 + 事件列表；副作用（存档、弹窗、Toast）集中在 App.tsx 的 absorb() 一处。

INPUT
用户操作 / 时间流逝
完成待办、放弃、换蛋；跨日与周一由 processTime 补结算
→
ENGINE
纯函数引擎
completeTodo / processTime …→ 新 GameState + GameEvent[]
→
ABSORB
副作用汇聚点
saveState 持久化；事件分流：揭露/破壳进弹窗队列，其余进 Toast
→
RENDER
React 渲染
工作间 / 图鉴 / 弹窗；生物与蛋由纯函数 SVG 组件绘制
  • 时间注入：引擎函数一律接收 today: 'YYYY-MM-DD' 参数，不内部取时钟——这是可测试性与 dev 时间偏移的基础。
  • 事件驱动演出：GameEvent（reveal / hatch / eggArrived / autoFail / forcedHatch / noEgg）由 UI 排队消费，一次完成跨多个阈值时揭露卡按序弹出。
  • 离线补结算：processTime 从 lastDay 逐日推进到今天，每日先处理周一事件再结算逾期，保证多日离线后的风险与周事件顺序正确。

§05

核心机制实现要点

5.1命运预掷 + 揭露懒掷（draw.ts）

预掷（蛋生成时，seed 固定）：孵化判定骰（0–100）、畸变预案（1–2 条）、变异骰、命名词根。懒掷（v0.2b 决议）：8 个特征改为揭露瞬间掷定并立即存档——结果由 (蛋种子, 槽位, 连击状态) 决定，互斥/联动从已揭露特征即时重算，连击加成得以生效且刷新依然无法重掷。休眠强制孵化时未揭露槽位静默补掷（无加成）。

// 揭露顺序（先形体后灵魂）
frame → limbs → head → mouth → surface → pattern → temperament → quirk
// 每槽：70% 主题池 / 30% 全量池 → 稀有度权重 N70:R25:L5 ×（连击时 R×1.5 / L×2）× 联动倍率

5.2时间结算（engine.processTime）

  • 逐日循环 lastDay+1 … today；每日先判 isMonday 走周事件，再结算逾期。
  • 周一：休眠棚每蛋 dormantWeeks++ 且 +8% 风险，>3 周强制孵化；台上未满蛋入棚（入棚即 +8%）并随即降临新蛋；棚满则蛋留台继续孵化。
  • 逾期：首日 +4%、此后每日 +2%，单条待办累计上限 12%；逾期满 7 天自动判失败再 +12%。风险落在结算当日孵化台上的蛋。
  • 事件化获取（v0.2 修订）：孵化完成即刻降临新蛋，顺延队列已移除；processTime 兜底"空台即领"，孵化台理论上不再空置。

5.3孵化判定

aberrant = destiny.judgmentRoll < egg.risk   // 判定骰在蛋生成时已注定
// 畸变 → 套用预案畸变（1–2 槽被覆盖），入标本室；正常 → 完整入册
// 档案快照 fedTodos（标题+难度），图鉴的"由 N 条待办喂大"由此而来

5.4周与日的边界处理

日戳统一 YYYY-MM-DD 字符串（本地日期生成、UTC 解释运算，避开 DST）；周以"该周周一的日戳"为标识。App 每 60 秒调一次 processTime，跨零点与跨周一在应用常开时也能触发。

5.5gen2 换轨：QMonster 语义特征（Phase 2，已于 2026-09-16 下线冻结）

现状：QMonster v0.3 运行时（../RandomPet 源码别名、181MB 素材同步、生成/渲染/目录代码、?qlab）已全部移除。旧 gen2 生物只读：立绘在下线前冻结为 512² data URL（record.qimageData）、语义特征展示名冻结为 record.qtraitNames，随存档导出携带，不再重绘也不再成长；台上/棚里的 gen2 蛋在读档迁移时换成小猫蛋（fseed = f{saveSalt}-{eggId}，菌沼 → 林苔）。若某源的旧生物当年未渲染成功（如 file://），冻结无从取图，永久显示爪印占位。以下为历史设计记录。

新蛋在 spawnEgg 时注定 qseed（q{saveSalt}-{seedTick}），走 QMonster 8 语义槽 × 61 特征（目录 v0.3.0）；不带 qseed 的旧蛋与既有 SVG 生物保留古典轨，双轨并存。

  • 引擎保持同步纯函数：异步的生成与渲染放在编排层 qmonster/orchestrator.ts——App 监听存档扫描待解析项（幂等，inflight 去重），结果经 setEggIdentity / setRecordSpec 纯函数回写。
  • 身份 vs 最终形态：揭露展示 normal 模式身份；孵化时按判定（正常/变异/畸变）以同 qseed 重新生成最终 spec——出生一刻的反转。变异率承接连击：判定时连击 ≥3 额外 +2%（古典轨连击仍加揭露稀有度）。
  • 确定性重试：任意 seed 可能撞渲染质检（SPEC_SOCKET_MISSING / 脸部越界等 error 诊断），按 seed → seed#1 → … 派生序列重试至通过（实测 ≤5 次收敛），同 baseSeed 永远同一只，防刷新重掷成立。
  • 立绘缓存：1024px 渲染 → WebP（PNG 兜底）入 IndexedDB（gsi-qmonster），键含目录/渲染器版本与 spec 的 canonical-JSON SHA-256；缓存丢失按存档里的权威 spec 重绘。
  • 命名：词根 + 最高稀有度语义特征展示名首字（撞字顺延次字）。
  • 暂缓项（Phase 3）：gen2 驻场成长（改用 QMonster rerollSlot 同槽重掷）；收集统计与目录的深度联动。

5.6gen3 小猫轨：QMonster v0.10 小猫组合（2026-09-15 接入正式流程）

新蛋在 spawnEgg 时注定 fseed（f{saveSalt}-{seedTick}）与 6 主题之一的 ftheme（未收集主题权重 ×2），并同步掷定正常形态 fplan（planFeline(fseed, ftheme, 'normal')，规则 feline-rules-v2）存入蛋——揭露卡直接取值，无需异步身份解析。theme 字段保留为旧主题回退映射，只供命运骰与旧代码路径使用。gen2（qseed）与古典蛋不再产生，但双轨代码保留供旧存档回放。

  • 7 槽揭露：阈值 F_THRESHOLDS = [14,28,42,56,70,84,98]，顺序花纹→表情→额顶→耳→颈→背→尾（revealCountFor / revealTotalFor 按轨别分派）；事件为 freveal，无异变的位置揭露为"安静"并提示破壳或有变数。
  • 破壳 = 出生一刻的反转：hatchEgg 按判定映射 fmode（畸变→aberration，变异→mutation，正常→normal）以同 fseed 重掷最终 fplan；命名（词根+最高层异变字+喵）与稀有度（max(最高异变层, 处数层)）在破壳瞬间即定，不再有"未名"过渡。
  • 编排层只管立绘：qmonster/feline/orchestrator.ts 调 SDK hatch(fseed, selections) 合成 1254² WebP，入 IndexedDB（键 = SDK cacheKey，绑定目录哈希+运行版本+规格哈希），并把 StoredFelineVisual 回写为 fvisual（setRecordFelineVisual 置 ready）；缓存丢失按 fvisual restore，字节一致。
  • SDK 接法：只消费 RandomPet master dist/hatchery 产物（npm run sync:hatchery → qmonster-assets/hatchery/<runtimeRevision>/，经 /qmonster/ 托管；同时把 qmonster.js 拷进 src/qmonster/feline/vendor/ 静态内联进应用），src/qmonster/feline/sdk.ts 钉 FELINE_RUNTIME_REVISION 并镜像类型；不再依赖源码别名。
  • 单文件（file://）形态：浏览器禁止 file:// 页面 fetch 本地文件，沿用 gsi-inbox.js 的 <script src> 注入通道——npm run release 经 scripts/build-release-assets.mjs 把目录 JSON 与 44 张 PNG 各写成一份 release/qmonster-files/*.js（约 69MB，gitignore；含 manifest.js），feline/offline.ts 按需注入并用 fetch 垫片把 SDK 对 http://qmonster.local/ 的请求接到注入数据（SDK 零改动，仍按字节校验 SHA-256）。发布必须整目录拷贝（HTML + qmonster-files/ + gsi-inbox.js）；只有 HTML 时降级为灰爪印占位并提示。?offline=1 可在 HTTP 下强制走此通道以便验证。
  • 异变分层：登记表 feline/mutations.ts 11 件（6 件原始 N；批次 1：颈膜/羽翼/焰尾 R，光环/龙翼 L），每次抽取先掷层（正常 N82/R15/L3、变异 N45/R40/L15、畸变 N30/R40/L30）再按主题亲和加权；正常态掷到 N 层时首件 80% 给标志异变，变异态首件必为标志。
  • UI：观察卡墙 / 机器 LED 按 7 槽；揭露卡 FRevealCard、破壳卡 FHatchCard（三段式共用 useHatchStage）；图鉴按 6 小猫主题分页 + 旧谱系页，统计花纹 x/6、异变 x/11、传说数；驻场用表情给气泡；蛋外观按主题色板与装饰（炎烬火星 / 云翼云片 / 曜庭菱纹 / 林苔蘑菇）。
  • 驻场成长（2026-09-16）：命中率沿用难度表与 3 次上限；"先长齐再升品"——异变少于 2 处先在空位长一件 N 级（主题亲和加权），否则同位置向上换层（只升一档 70 / 跳档 30）；命名不变、稀有度重算，形象清空缓存键与 fvisual 置 pending 由编排层重新合成；事件 fgrow + 成长卡。顶配（五位置皆最高层）无法成长且不消耗次数。
  • 暂缓项：批次 2 素材（耳位蝠翼耳 R 需 6 花纹、光环加粗）。
§06

渲染管线与画风

6.1生物渲染器（Creature.tsx）

生物 = 特征ID×8 + 主题色板 + seed 的纯函数。图层顺序：

地影 → 异能微光 → 附肢 → 蒙版躯体(底色/渐变 + 纹样 + 表皮内效 + 体积光 + 肚皮布片)
     → 表皮外饰 → 头部与眼 + 腮红 → 口器
  • 蒙版技巧：躯体剪影画进 <mask>，纹样/材质/光影以整幅矩形绘制后被剪影裁切——蛇形等描边型剪影也能统一处理。
  • 造型基准（可爱治愈）：大头身比、圆润无锐角、大眼双高光、全员腮红、粉彩化配色（底色向白偏移 16%、暗部收敛）。
  • 畸变渲染：错位=器官偏移、未成形=槽位半透明、色彩失谐=失谐色板、静默=无动画、外溢=模糊、逆生长=整体缩放。

6.2五种画风（滤镜层，特征零重画）

画风实现定位
flat 扁平剪纸纯色块面基线对照
soft 软立体径向渐变 + 高光/体积影 + feDropShadow安全耐看
sticker 贴纸卡通feMorphology 双层膨胀（深描边+白贴纸边）+ 提饱和当前默认，表情包/分享气质
ink 水彩图鉴feTurbulence 位移抖动轮廓 + 墨线环 + 纸纹颗粒乘算博物志氛围，宜纸面场景
plush 毛绒玩偶噪声凹凸 + feDiffuseLighting 绒面 + 双重扰动毛边 + 缝线布片；脸部件独立于绒面（塑料眼+刺绣脸）实体陪伴感，候选主风格
滤镜层经验：光照/乘算类滤镜会洗淡颜色，尾部需补饱和（plush 补了 saturate 1.28）；发光大色块（异能微光）必须放在描边滤镜组之外，否则半透明 alpha 会被膨胀出脏环；「双目下垂」类表情用闭眼「˘˘」曲线才治愈，半睁眼读作不耐烦。

6.3蛋渲染器（Egg.tsx）

主题化外观（深海气泡/菌沼活蘑菇/幽影眨眼暗涡）+ 状态可视化：微光强度 ∝ 孵化点，裂纹分档出现于风险 >15/30/50/70%，≥60 点透出内部剪影。

6.4QMonster 位图管线（gen2 · Phase 2）

gen2 生物立绘由 @qmonster/generator-core（生成 spec）+ @qmonster/renderer-canvas（canvas 合成，调色板蒙版走 getImageData）渲染，素材经 scripts/sync-qmonster.mjs 从 ../RandomPet 同步到 qmonster-assets/（gitignore）。运行时依赖以 vite alias 指向 RandomPet 源码；类型检查用本地最小 .d.ts 镜像解耦（src/qmonster/types/）。UI 侧 QCreatureImg 从 IndexedDB 取 Blob 建 objectURL，pending 态呼吸占位；本章 §6.1–§6.2 的 SVG 管线自此专属古典轨（StyleLab 保留为古典画风实验室）。

6.5小猫轨位图管线（gen3）

gen3 立绘全部由 SDK qmonster.js（esbuild 自包含 ESM，运行时按固定 URL 动态 import）在浏览器 OffscreenCanvas 上合成：SDK 校验目录字节 SHA-256 与快照一致、按 selections 解析投影、清除原耳/原尾区域、按异变 id 取模板变换（批次 1 新件为恒等变换）后输出 WebP；孵化器不接触渲染细节，也不重画任何部件。QCreatureImg 对 gen2/gen3 统一：gen3 先查 IndexedDB 再按 fvisual 重绘；gen2 只读冻结 data URL（其次本源旧缓存），不再重绘。

§07

数据结构

单一存档对象存于 localStorage key gsi-save-v1，含 version 字段供后续迁移。要点：

GameState { version, gsiCounter, seedTick, saveSalt,   // 存档级随机盐
            currentEgg, shed[≤3],
            todos[], codex[], lastDay, firstDay }

Egg   { id, theme, seed, points, risk, destiny,        // 命运在生成时已注定
        dormantWeeks, fedBy[] }

已知问题与约定

  • 无 git 仓库：项目尚未 git init。建议尽早初始化并做首次提交（参照斗蛐惯例可直接在 main 上开发，代价是提交前测试必须全绿）。
  • 版本升级迁移：存档带 version，加字段时在 storage.loadState 做向后兼容填默认值，不清档。
  • 风险归属：逾期风险落在结算当日台上的蛋；台空则该日风险落空（对用户有利，接受）。
  • 驻场时段动画：夜行性格按本地时钟 20:00–6:00 切换行为，纯展示层，不进存档。
  • 性能：图鉴卡片多时 SVG 滤镜（尤其 plush 的光照）有开销，图鉴内已关 idle 动画；若入册量大再考虑虚拟滚动或缩略图缓存。
  • 设计文档同步：数值改动需回写设计文档（Artifact 同链接重发 + docs/design-v0.1.html 同步），避免两份文档漂移。
